# 「校练」接口契约 v1.0（前端 ↔ 后端）

> 状态：草案冻结（Schema v1.0）。前端已按本契约实现 mock 服务层（`mini-program/utils/mock.js`），后端 FastAPI 按本契约实现后，前端把 `utils/config.js` 的 `useMock` 改为 `false` 即可联调。
> 配套：[前端实现规范](../01-前端/前端实现规范.md)、[项目功能与技术框架](../../项目功能与技术框架.md)

## 1. 通用约定

- 协议：HTTPS，域名需 ICP 备案；小程序后台配置 request 合法域名。
- Base URL：`https://<api-host>/api/v1`
- 请求头：`content-type: application/json`、`X-Client: miniprogram`、`X-Client-Version`、`X-Schema-Version`
- 统一返回：

```json
{ "code": 0, "data": {}, "msg": "ok" }
```

- 前端请求层会剥离外壳、code!==0 时 reject `{ code, msg, data }` 并统一提示（除 silent 调用）。
- 分页/列表统一放 `data` 内（如 `{ records, total }`）。

### 1.1 错误码

| code | 含义 | 前端处理 |
|---|---|---|
| 0 | 成功 | 渲染 |
| 1001 | 参数校验失败，`data.errors` 给出字段错误 | 表单内联报错 |
| 1002 | 未登录 / 登录过期 | 重新登录（openid 换 session） |
| 1003 | 资源不存在（计划/动作/训练日） | 空状态或重新生成 |
| 2001 | 无可用动作（约束组合过严） | 提示放宽条件 / 咨询体育老师 |
| 3001 | LLM 解析 / 解释失败（已重试 2 次） | 降级表单 / 跳过解释，不阻塞 |
| 4040 | 接口不存在（仅 mock 调试） | 前端提示版本不匹配 |
| 5000 | 服务器内部错误 / 网络错误 | 统一错误提示 + 重试 |

| 方法 | 路径 | 用途 |

| POST | `/plan/explain` | 计划解释（LLM 调用点 2，只读） |

| GET | `/logs/intercepts` | 安全拦截日志（管理/演示） |

## 3. 关键请求 / 响应摘要

### 3.1 POST /profile

```json
{
  "profile": {
    "gender": "male", "target_events": ["run_1000", "jump_long"],
    "event_levels": { "run_1000": "fail", "jump_long": "pass" },
    "self_level": "weak", "equipment": ["band"], "space": "dorm",
    "time_per_session": 30, "weekly_frequency": 3, "body_limits": ["knee"],
    "goal": "score_up", "test_date": "2026-12-13", "natural_language": ""
  }
}
```
响应：`{ "profile": {…含 user_id/updated_at}, "needs_replan": true }`

### 3.2 POST /profile/parse

请求 `{ "text": "每周三次，每次 30 分钟，宿舍里只有弹力带，膝盖有点不舒服" }`
响应：`{ "parsed": {…仅包含识别到的字段}, "filled_fields": ["可用器械", …], "confidence": 0.67, "retry_count": 0 }`
失败：code=3001（Schema 校验失败且重试 2 次后），前端降级表单。

### 3.3 POST /diagnosis

请求 `{ "profile": {...} }`；响应结构见前端规范 6.2（items/allocation/weak_dimensions/summary）。

### 3.4 POST /plan/generate

请求 `{ "profile": {...}, "diagnosis": {...} }`；响应：
```json
{ "plan": {…}, "diagnosis": {…}, "intercept_count": 6, "candidate_count": 28 }
```
规则：4 周 = 准备期/进展期/减量期（按距体测天数）；每周训练次数=用户设置；单次动作数量按 15/30/45 分钟；四类硬过滤（器械/空间/身体限制/能力门槛）；所有被拦截动作进 `plan.safety_intercepts`。

### 3.5 POST /checkin

请求结构见前端规范 6.4。响应：
```json
{
  "record": {...},
  "stats": { "week_no": 1, "total_sessions": 3, "done_count": 1, "partial_count": 1,
             "completion_rate": 0.67, "avg_rpe": 7.5, "discomfort_count": 1, "streak": 1 },
  "safety_review": { "triggered": true, "limits": ["knee"], "limit_labels": ["膝盖不适"], "message": "…" }
}
```

### 3.6 POST /feedback/weekly

请求结构见前端规范 6.5。规则分支（表驱动，后端规则引擎与 `data/rules.js` 对应）：

| rule_id | 命中条件 | 调整类型 |
|---|---|---|
| ADJ-01 | 本周有不适反馈 | reduce（减量 + 安全复查） |
| ADJ-02 | 完成率 < 0.5 | rest（降低目标） |
| ADJ-03 | 平均 RPE ≥ 8.5 | reduce |
| ADJ-04 | 整体感受 = 偏累 | reduce |
| ADJ-05 | 完成率 ≥ 0.9 且 RPE ≤ 6 且 感受=轻松 | upgrade（升阶） |
| ADJ-06 | 完成率 ≥ 0.8 | progress（正常推进） |
| DEFAULT | 其余 | progress |

响应：`{ "record": {...}, "adjustment": {...}, "next_week": { "available": true, "week": {...}, "safety_changes": [...] }, "history": [...] }`

### 3.7 GET /actions/{action_id}

响应结构见前端规范 6.6。`demo.type=frames` 时 `frames` 为静态资源路径数组（可由后端 CDN 提供）；`demo.type=text` 时前端展示图文要点。

### 3.8 GET /diet/tips

Query：`?date=YYYY-MM-DD&training_type=strength|cardio|mobility|rest&foods=[{"food_id":"egg","portion":1}]`（foods 为 JSON 序列化或后端改为 POST，联调时确认）。
响应结构见前端规范 6.7；必须携带 `disclaimer`。
