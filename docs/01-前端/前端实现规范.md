### 3.3 交互规范

- 主 CTA 点击必须有反馈：loading（request 层统一处理）/ disabled / toast。
- 所有可跳转动作示范的入口：`wx.navigateTo({ url: '/pages/action/action?id=' + actionId })`。
- Tab 页之间跳转必须 `wx.switchTab`；非 tab 页（约束输入、动作示范）用 `navigateTo` / `navigateBack` / `reLaunch`。
- Tab 页在 `onShow` 中调用 `reminder.refreshBadge()`；数据变更后刷新页面数据。
- 计划页/打卡页/反馈页开启下拉刷新（页面 json `"enablePullDownRefresh": true`），`onPullDownRefresh` 中重新拉取并 `wx.stopPullDownRefresh()`。
- 空数据、接口失败、无计划都要有明确出口按钮，不允许白屏。
- Emoji 仅作轻量图标（如 🏃 💡 🛡️），不要用 emoji 替代主视觉。

## 4. 公共组件 API（已冻结，禁止改签名；页面按此调用）

> 所有组件使用 `styleIsolation: isolated`，组件内不使用 app.wxss 的类；页面传 props / 监听 events。

### 4.1 `plan-card` 计划卡片

```xml
<plan-card
  session="{{session}}"
  mode="full"                 <!-- full | compact -->
  show-status="{{true}}"
  bindactiontap="onActionTap"  <!-- { actionId, actionName, index } -->
  bindcheckin="onCheckin"      <!-- { sessionId } -->
></plan-card>
```
渲染：训练日标签/日期、标题、时长/地点、动作标签列表（内部使用 action-tag）、备注、底部“去打卡”按钮。
`session` 结构见第 6.3 节；打卡页如需勾选完成动作，自行渲染动作行，不要复用 full 模式。

### 4.2 `action-tag` 动作标签

```xml
<action-tag action="{{action}}" index="{{index}}" show-meta="{{true}}" bindselect="onSelect"></action-tag>
```
事件 `select`：`{ actionId, actionName, index }`。

### 4.3 `rpe-slider` RPE 滑条

```xml
<rpe-slider value="{{rpe}}" bindchange="onRpeChange"></rpe-slider>
```
事件 `change`：`{ value }`（1-10）。**受控组件**：父级需把 `e.detail.value` 写回 data，否则视图仅本地变化。

### 4.4 `tag-picker` 标签选择器

```xml
<tag-picker
  options="{{options}}"
  value="{{value}}"
  multiple="{{true}}"
  exclusive-value="none"
  max="{{3}}"
  layout="cards"              <!-- chips | cards -->
  bindchange="onChange"        <!-- { value, changed } -->
></tag-picker>
```
- `multiple` 时 `value` 是数组，单选时是标量。
- `exclusiveValue`：实现「无器械 / 无限制 / 没有不适」这类互斥项（选中它清空其他；选其他清空它）。
- `layout="cards"` 为两列卡片（带 desc），适合自评/时长/空间类选项。

### 4.5 `stepper` 步进器

```xml
<stepper value="{{freq}}" min="{{2}}" max="{{5}}" unit="次/周" bindchange="onFreqChange"></stepper>
```
事件 `change`：`{ value }`。

### 4.6 `state-view` 三态容器

```xml
<state-view state="{{viewState}}" text="{{errorText}}" bindretry="loadData">
  <!-- state === 'done' 时渲染插槽内容 -->
</state-view>
```
`viewState`: `loading | error | done`。

### 4.7 `empty-state` 空状态

```xml
<empty-state icon="🏃" title="还没有训练计划" desc="先完成约束输入…" action-text="去填写约束" bindaction="goConstraints"></empty-state>
```

### 4.8 `safety-banner` 安全拦截提示

```xml
<safety-banner intercepts="{{plan.safety_intercepts}}" title="安全拦截" collapsible="{{true}}"></safety-banner>
```
无拦截时不渲染；展开显示每条 `rule_id / 动作 / 原因 / 替换动作`。

## 5. 接口层 `utils/api.js`（页面只调用这些函数）

统一说明：返回 `Promise`，成功 resolve **data**（已剥离 `{code,data,msg}` 外壳），失败 reject `{ code, msg, data }`。
错误码：`1001` 参数校验失败、`1002` 未登录/过期、`1003` 资源不存在、`2001` 无可用动作、`3001` LLM 解析失败（降级）、`4040` 接口不存在、`5000` 服务端/网络错误。

| 函数 | 入参 | 成功返回（data） | 使用页面 |
|---|---|---|---|
| `submitProfile(profile)` | profile 对象 | `{profile, needs_replan, updated_at}` | 约束输入 |
| `getProfile()` | - | `{profile: Object\|null}` | 约束输入 |
| `parseNaturalLanguage(text)` | `{text}`，已静默错误 | `{parsed, filled_fields, confidence, retry_count}`；失败 reject `3001` | 约束输入 |
| `getDiagnosis(profile)` | profile | diagnosis（第 6.2 节） | 约束输入（生成前） |
| `generatePlan({profile, diagnosis})` | - | `{plan, diagnosis, intercept_count, candidate_count}` | 约束输入、计划页重算 |
| `getCurrentPlan()` | - | `{plan: Plan\|null, stale, days_old}` | 计划、打卡、反馈、饮食 |
| `getPlan(planId)` | - | `{plan, stale, days_old}` | 计划页（可选） |
| `explainPlan(planId)` | - | `{plan_id, text, model, generated_at, checks}` | 计划页 |
| `getAction(actionId)` | - | action detail（第 6.6 节） | 动作示范 |
| `checkin(payload)` | 第 6.4 节 | `{record, stats, safety_review, plan_id}` | 提醒打卡 |
| `getCheckins({week_no})` | - | `{records, stats, streak, week_no, total}` | 打卡、周反馈 |
| `getWeeklyFeedback({week_no})` | - | `{record, stats, history, plan_summary, message}`；无计划时 `plan_summary=null` | 周反馈 |
| `submitWeeklyFeedback(payload)` | 第 6.5 节 | `{record, adjustment, next_week, history, plan_id}` | 周反馈 |
| `getDietTips({date, training_type, foods})` | `foods: [{food_id, portion}]` | `{date, training_type, training_label, training_session, intake, tips, food_table, dimensions, disclaimer}` | 饮食提示 |
| `getInterceptLogs()` | - | `{plan_id, total, logs, by_type, safety_table_version}` | 计划页（可选） |

调用约定：

```js
const api = require('../../utils/api');

loadData() {
  this.setData({ viewState: 'loading' });
  api.getCurrentPlan()
    .then((res) => {
      if (!res.plan) { this.setData({ viewState: 'done', plan: null }); return; }
      this.setData({ viewState: 'done', plan: res.plan, stale: res.stale, daysOld: res.days_old });
    })
    .catch((err) => {
      // 1003 等业务错误可降级为空态；其它错误显示 error 态
      this.setData({ viewState: err.code === 1003 ? 'done' : 'error', errorText: err.msg });
    });
}
```

- LLM 相关接口（`parseNaturalLanguage`、`explainPlan`）失败**不得阻塞主流程**：解析失败 → 手动表单继续；解释失败 → 提示“暂时无法生成解释，不影响训练”。
- 网络/mock 请求层会自动 toast 错误（`silent` 的除外），页面不要重复 toast 同一错误。

## 7. 六个页面的详细规格

### 7.1 约束输入页 `pages/constraints/constraints`（入口页，非 tab）

**目标**：把“体测项目、当前成绩、器械、空间、单次时间、身体限制、目标、体测日期”采集为结构化画像；自然语言入口失败可降级表单；提交后完成诊断 + 生成计划并跳转计划页。

- 页面 json：`navigationBarTitleText: "填写训练约束"`，`navigationBarBackgroundColor: "#FF6B2C"`，白字。
- Hero：kicker「STEP 0 · 先定约束」；title「先定约束，再谈计划」；sub「校园里能用的器械、能挤出的时间、身体的小状况，都会作为硬约束参与计算」；meta 三个数据块：`4 周周期化`、`4 类硬过滤`、`安全优先`。
- **已有画像时的进入逻辑**：`onLoad` 调用 `api.getProfile()`；若已有 profile：
  - 若 `options.edit === '1'`（从计划页来）→ 表单用已有值预填，页面顶部显示提示条「修改约束后需要重新生成计划」；
  - 否则（冷启动入口页）→ 短暂展示后 `wx.switchTab({url:'/pages/plan/plan'})` 回计划页（避免每次冷启动停在表单）；若计划也不存在则留在本页。
- **AI 自然语言补充卡**（放表单最上方）：

## 8. 编码约定

1. **ES6**：`const/let`、箭头函数、模板字符串、Promise/async-await 可用；**不使用可选链 `?.`、空值合并 `??`**（兼容旧基础库）。
2. 页面 JS 顶部统一 `const api = require('../../utils/api');`，其余按需 require；不要写绝对路径（小程序不支持）。
3. `setData` 只更新必要字段，列表数据一次性 setData；避免在循环里 setData。
4. 事件命名：`onXxx`；页面方法不要与生命周期重名。
5. 所有数据页面实现三态：`viewState = loading | error | done`；数据为空时用 empty-state（可理解为 done + 空数据）。
6. 定时器/监听必须在 `onHide/onUnload` 清理。
7. 页面 json 的 `usingComponents` 只声明实际用到的组件。
8. 注释使用中文，关键逻辑写清「为什么」；不要留 TODO/占位逻辑。
9. 不引入 npm 包、不改 app.json 的页面清单和 tabBar、不改 utils/data/components（如需扩展先找 Lead 协调）。
10. 演示稳定性：禁止出现 `undefined` 文本、破图、白屏、按钮点击无响应；所有图片路径必须存在（assets 由素材任务产出）。
